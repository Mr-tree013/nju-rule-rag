## 二、作品目标

**NJU Rule RAG** 是一个面向南京大学本科生的**校规与教务流程智能问答系统**。学生用自然语言提问（如"补考没过怎么办""缓考怎么申请"），系统自动从 147 份校规文档中检索相关内容，由本地大语言模型（Qwen3-8B）生成带来源引用的回答，并根据置信度自动分级——自信回答、谨慎回答或建议转人工咨询。

### 核心目标

| 目标 | 说明 |
|------|------|
| **降低信息门槛** | 校规分散在教务处网站、学生手册、通知公告等各处，新生难以快速定位。本项目提供自然语言问答入口，降低查找成本 |
| **防止幻觉输出** | 校规场景对准确性要求极高（比如补考条件、退学后果说错了后果严重），系统内置多层护栏：事实核查、来源引用、拒答机制、风险分级 |
| **多交互入口** | 同时提供 REST API、QQ 群机器人两种使用方式，前者方便集成前端/小程序，后者降低学生使用门槛 |

### 核心功能

- 自然语言提问，基于本地 Qwen3-8B 生成带来源引用的回答
- 三级风险分类（低/中/高），高风险问题自动切换到 DeepSeek 并追加免责声明
- NER 事实核查：提取答案中的数字、日期、URL、金额，与来源文档逐条比对，未匹配的实体自动 hedge 或删除
- 三级置信度分级：Tier 1 自信回答 / Tier 2 保守回答 / Tier 3 直接转人工（跳过 LLM）
- 22 个主题自动识别，对相关文档 1.2× 检索加权
- 混合检索：BM25 关键词 + BGE-M3 语义向量 + 优先级加权
- SSE 流式输出，token 级实时生成 + 事实核查修正
- QQ 群机器人接入（NapCat + OneBot v11）

## 五、使用指南

### 5.1 部署指南

#### 环境要求

| 项目 | 要求 |
|------|------|
| 操作系统 | Linux（推荐 WSL2 Ubuntu on Windows 11） |
| Python | 3.10+ |
| GPU | NVIDIA RTX 4070 Ti Super 16GB（或其他 ≥16GB 显存显卡） |
| CUDA | 12.4 |
| Ollama | 0.24.0 |
| 内存 | ≥32GB |

#### 快速部署（一行命令）

```bash
# 1. 克隆仓库
git clone https://github.com/Mr-tree013/nju-rule-rag.git
cd nju-rule-rag

# 2. 配置环境变量
cp .env.example .env
# 编辑 .env，填入 LLM_API_KEY=ollama（本地 Ollama 无需真实 key）

# 3. 一键启动（自动创建 venv、安装依赖、运行预检、启动服务）
./scripts/start_server.sh
```

启动脚本自动完成：
- 创建并激活 Python 虚拟环境
- 安装依赖（torch、sentence-transformers、chromadb 等）
- 配置代理环境变量（WSL2 继承 Windows 代理，Ollama 本地绕行）
- GPU 显存优化（expandable_segments、KV cache q8_0）
- 运行预检诊断（CUDA、模型、Ollama、索引）
- 启动 uvicorn（端口 8000）

#### Docker 部署

```bash
docker compose up -d    # CPU 模式，构建并启动在端口 8000
```

> 注意：Docker 内 GPU 不可用，向量检索会比较慢。生产环境推荐原生部署。

#### Ollama 环境配置

在启动 `ollama serve` 前设置（或 `source scripts/ollama_env.sh`）：

```bash
export OLLAMA_FLASH_ATTENTION=1      # 启用 Flash Attention
export OLLAMA_KV_CACHE_TYPE=q8_0     # 8-bit KV cache（~50% 显存节省）
export OLLAMA_KEEP_ALIVE=24h         # 模型常驻内存，避免冷启动
```

创建 no-think 变体模型：

```bash
ollama create qwen3:8b-nothink -f scripts/modelfile.qwen3-nothink
```

#### 验证部署

```bash
# 健康检查
curl http://127.0.0.1:8000/health

# 深度诊断（GPU/Ollama/索引/缓存）
curl http://127.0.0.1:8000/admin/health_deep

# 测试问答
curl -X POST http://127.0.0.1:8000/ask \
  -H "Content-Type: application/json" \
  -d '{"question":"缓考怎么申请？"}'
```

### 5.2 使用指南

#### 方式一：API 调用

**非流式问答**（返回完整结果）：

```bash
curl -X POST http://127.0.0.1:8000/ask \
  -H "Content-Type: application/json" \
  -d '{"question":"补考没过怎么办"}'
```

响应示例：

```json
{
  "question": "补考没过怎么办",
  "answer": "只能重修，补考就一次机会。没过的话这门课得跟着下一届重新上...",
  "risk_level": "medium",
  "need_human_confirm": true,
  "sources": [
    {"chunk_id": "...", "title": "补考管理实施细则", "source_id": "nju-jw-005", ...}
  ],
  "debug": {
    "latency": 1.76,
    "confidence_tier": "1",
    "llm_used": "qwen3:8b-nothink",
    ...
  }
}
```

**流式问答**（SSE，token 级实时输出）：

```bash
curl -N -X POST http://127.0.0.1:8000/ask/stream \
  -H "Content-Type: application/json" \
  -d '{"question":"转专业需要什么条件"}'
```

#### 方式二：QQ 群机器人

1. 下载 NapCatQQ，注册 QQ 小号并扫码登录
2. 在 NapCat 中配置 OneBot v11 HTTP 回调地址为 `http://127.0.0.1:8000/qq`
3. 将 QQ 小号加入目标 QQ 群
4. 群内使用：`@机器人 /问 缓考在哪里申请` 或 `@机器人 /ask 补考没过怎么办`

机器人自动回复，格式为：【结论】【依据】【提醒】三段式。

#### 方式三：内置管理接口

```bash
# 提交新文档入库
curl -X POST http://127.0.0.1:8000/admin/ingest_url \
  -H "Content-Type: application/json" \
  -d '{"url": "https://jw.nju.edu.cn/xxx", "source_id": "nju-jw-xxx"}'

# 查看待审核文档
curl http://127.0.0.1:8000/admin/staging

# 查看缓存统计
curl http://127.0.0.1:8000/cache/stats

# 提交用户反馈
curl -X POST http://127.0.0.1:8000/feedback \
  -H "Content-Type: application/json" \
  -d '{"question":"补考没过怎么办","answer":"...","rating":"up","comment":""}'
```

## 八、已知限制与未来计划

### 已知限制

1. **上下文精度低（0.12）**：检索返回的 10 个 chunk 中平均仅 ~1 个真正相关，是 faithfulness 进一步提升的主要瓶颈
2. **部分主题文档覆盖不足**：社团、考研、体育课项目、校历等话题仅有 1-2 份源文档
3. **LLM-as-Judge 偏差**：DeepSeek judge 在忠实度维度与人类评分 Spearman 相关性仅 0.26，评测可信度仍需提升
4. **HuggingFace 模型首次加载需联网**：BGE-M3 嵌入模型约 2.2GB，离线环境需预下载

### 未来计划

- LoRA v3 微调上线（当前 GGUF 已就绪，待验证）
- 检索质量系统性提升（Route A 路线图）
- 积累真实用户反馈数据建设飞轮
- BGE-Reranker 在 NJU 领域数据上微调，改善排序区分度
